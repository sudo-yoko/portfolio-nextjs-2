Q. my-monorepo-1のenv.helper.vlidated.test.tsで、
clear & npm run node:test -- --test-name-pattern=test1-4 src/env/env.helper.validated.test.tsのように
個別にテストケースを実行すると成功しますが、
clear & npm run node:test -- src/env/env.helper.validated.test.tsのようにすべてのテストケースを実行すると
test1-4とtest2-3が失敗するのはどうしてですか

A. 原因は、env.helper.validated のモジュールキャッシュにより、最初のテストで読み込んだ env のモックが参照され続けることです。

全件実行では、次の順序になります。

1. test1-1 が env を { next_public_fw_debug_logger: undefined } にモックする。
2. env.helper.validated を初めて import し、そのモックへの参照が確定する。
3. 後続テストで同じヘルパーを import しても、キャッシュ済みのモジュールが返される。
4. t.mock.module() で新しいモックを登録しても、読み込み済みのヘルパーが持つ参照は切り替わらない。

Node.js の仕様でも、モック前に取得したモジュールへの参照は影響を受けないと説明されています。
公式ドキュメント:
https://nodejs.org/download/release/v26.7.0/docs/api/test.html#mockmodulespecifier-options

その結果、以下のようになります。

・test1-4
  ヘルパーが参照する next_public_fw_debug_logger は undefined のままです。
  false が返り、期待する true と一致しません。

・test2-3
  ヘルパーが参照する node_env は undefined です。
  'production' が返らず、例外が発生します。

個別実行なら、そのテストのモックを設定した後にヘルパーが初めて読み込まれるため、成功します。

修正方法としては、env を一度だけモックし、同じオブジェクトのプロパティを各テストで変更する方法が使えます。

    import { mock } from 'node:test';

    const mockedEnv = {
        next_public_fw_debug_logger: undefined as string | undefined,
        node_env: undefined as string | undefined,
    };

    // 最初のヘルパーの import より前に登録する
    mock.module('@/env/src/internal/env.ts', {
        namedExports: { env: mockedEnv },
    });

    const { envFwDebugLogger, envNodeEnvNext } =
        await import('@/env/src/internal/env.helper.validated');

各テストでは mockedEnv.next_public_fw_debug_logger = '1' などと設定します。
この方式では状態を共有するので、各テスト前に値をリセットし、並列実行を避けます。

また、test2-1 と test2-2 は例外を catch して表示するだけなので、例外が発生しなくても成功してしまいます。
例外を検証するなら、次のようにします。

assert.throws(() => envNodeEnvNext(), /未定義の環境変数値です/);

検証上の制限:
こちらの環境では実行がファイル単位のエラーで終了し、同じ失敗内容までは再現できていません。
上記は、実際のコードの読み込み順とモックの仕様から判断した原因です。
