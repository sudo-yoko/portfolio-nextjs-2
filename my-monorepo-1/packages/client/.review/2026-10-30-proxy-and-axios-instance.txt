会話記録：プロキシ設定の設計と Axios インスタンスの一意性
日付：2026-10-30

【ユーザー】
my-monorepo-1のpackagesで、clientのaxios-adapter.s.tsとclient.s.ts、envのenv.s.helper.validated.tsの
envProxySettingsの設計を見る。環境変数からプロキシ設定を取得してaxiosClientの引数に渡す実装の仕方を改善できますか

【回答】
3ファイルを確認しました。環境変数の取得を env、クライアントの組み立てを client.s.ts、Axios 固有の処理をアダプターに置く現在の分担は、
そのまま活かせます。改善したいのは、プロキシの有無と初期化の扱いです。

1. undefined と「プロキシ無効」を区別する

現在の axiosClient() は proxy: undefined になります。Axios ではこれでも HTTP_PROXY / HTTPS_PROXY などが参照されるため、
バックエンド通信が必ず直接接続になるわけではありません。明示的に無効化するには false が必要です。
参照：https://axios-http.com/docs/req_config

引数をオプションオブジェクトにすると意図を表現できます。

    type AxiosClientOptions = {
        proxy: AxiosProxyConfig | false;
    };

    export const axiosClient = ({ proxy }: AxiosClientOptions): Client => ({
        send: async (config) => {
            // 既存の処理
            // axiosConfig.proxy = proxy;
        },
    });

    // client.s.ts
    const backendClient = axiosClient({ proxy: false });

    export const externalClient = axiosClient({
        proxy: envProxySettings(),
    });

これは「バックエンドは直接接続、外部通信は指定プロキシ」という方針の場合です。標準環境変数への委譲も必要なら、
undefined を許可してその意味を明記します。

2. envProxySettings は Axios に依存しない型を返す

現状も Axios を import していない点は良い設計です。戻り値の protocol: string を狭めると、検証結果を型でも表現できます。

    export type ProxySettings = {
        protocol: 'http' | 'https';
        host: string;
        port: number;
    };

    export function envProxySettings(): ProxySettings {
        const protocol = envProtocol('PROXY_PROTOCOL');
        const host = envString('PROXY_HOST').trim();
        const port = envNumber('PROXY_PORT');

        if (!Number.isInteger(port) || port < 1 || port > 65535) {
            throw new Error('PROXY_PORT は 1〜65535 の整数で指定してください。');
        }

        return { protocol, host, port };
    }

現在の envNumber() は小数や Infinity も通すため、ポート専用の検証を追加する意味があります。
汎用の数値検証にポートの制約を混ぜる必要はありません。

3. import 時にプロキシ設定を必須にするかを決める

現在は externalClient をモジュール直下で生成するため、同じファイルの backendClient だけを使う場合も PROXY_* が必須になります。

外部通信が任意の機能なら、バックエンド用と外部通信用のモジュールを分けるか、外部クライアントを初回利用時に生成する形が適しています。
アプリ全体でプロキシ設定が必須なら、現在の早期検証も妥当です。

まずは、引数を { proxy } にする、直接接続を false で明示する、ポートを検証する、の3点を勧めます。
共有 Axios インスタンスにリクエスト単位で設定を渡す現在の方式は、この改善のために変更する必要はありません。

ファイルはまだ変更していません。

【ユーザー】
axios-adapters.s.tsで、axiosインスタンスは一意になるようにしていますが、ほぼ同時に複数axiosのリクエストが発生した場合でも一意は保証されますか

【回答】
はい。現在の実装なら、同じモジュールインスタンス内では、ほぼ同時に複数のリクエストが発生しても Axios インスタンスは1つです。

    const axiosInstance = (() => {
        return axios.create();
    })();

この処理はモジュールの初期化時に同期的に実行されます。リクエストごとに実行される処理ではないため、
複数の send() は、作成済みの同じ axiosInstance を使用します。backendClient と externalClient もこれを共有します。

また、現在はリクエストごとに axiosConfig を作成しているので、同時実行によって一方の proxy がもう一方の設定を上書きする構造にはなっていません。

ただし、アプリケーション全体で必ず1つ、という保証ではありません。別プロセス・別ワーカー・別サーバー実行環境では、
それぞれインスタンスが作られます。開発中のモジュール再読み込みでも再作成される場合があります。

そのため、コメントは次のようにすると正確です。

    // このモジュールのインスタンス内で共有する Axios インスタンス
    const axiosInstance = axios.create();

初期化ログが必要なら、現在の即時実行関数のままで問題ありません。

【ユーザー】
モジュールのimportが複数から同時にされた場合でも、一意は保証されますか

【回答】
はい。同じ実行環境で、同じモジュールとして解決される限り、複数箇所から同時に import しても1つです。

JavaScript のモジュールは初回に評価され、その結果が再利用されます。import ごとに次のコードが実行されるわけではありません。

    const axiosInstance = (() => {
        return axios.create(); // モジュールの初回評価時だけ実行
    })();

例えば、A と B が同じ axios-adapter.s.ts を import しても、同じ axiosInstance を共有します。
同時 import に備えたロック処理は不要です。一意になる理由は即時実行関数ではなく、モジュールの評価・再利用の仕組みです。

ただし、別プロセス・別ワーカーや、バンドルの分離などで別のモジュールとして読み込まれる場合は、それぞれに作成されます。
保証の範囲は「同じモジュールインスタンス内」です。

【ユーザー】
backendClientとexternalClientをモジュールを分けた場合、index.s.tsで公開する場合でもそれは意味がありますか

【回答】
index.s.ts で両方を再エクスポートする場合、モジュールを分けるだけでは、プロキシ設定の読み取りを避けられるとは限りません。

例えば、次の構成です。

    // index.s.ts
    export { default } from './backend-client.s';
    export { externalClient } from './external-client.s';

    // external-client.s.ts
    export const externalClient = axiosClient({
        proxy: envProxySettings(),
    });

利用側がバックエンド用だけを import しても、通常の ESM の評価では、再エクスポート先の外部通信用モジュールも評価されます。
そのため、envProxySettings() が実行されます。バンドラーの tree shaking で除去される可能性はありますが、それに依存した設計は避けたいです。

同じ index.s.ts から公開するなら、外部クライアントを初回利用時に生成する方法が確実です。

    // external-client.s.ts
    let instance: Client | undefined;

    export function getExternalClient(): Client {
        return instance ??= axiosClient({
            proxy: envProxySettings(),
        });
    }

    // index.s.ts
    export { default } from './backend-client.s';
    export { getExternalClient } from './external-client.s';

これなら、import 時にはプロキシ設定を読み取らず、getExternalClient() を初めて呼んだ時に検証・生成します。

別案として、パッケージの公開先を @my/client/server/backend と @my/client/server/external に分け、
利用側が直接 import する方法もあります。その場合は、モジュールを分けることで初期化も分離できます。
