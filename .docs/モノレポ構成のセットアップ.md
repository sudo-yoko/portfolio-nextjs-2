# npm workspaces を使ったモノレポ構築

1.  ルートディレクトリの作成

    ルートフォルダを作成し、npm init -y で package.json を自動生成する。

    ```bash
    mkdir my-monorepo-1
    cd my-monorepo-1
    npm init
    ```

    実行結果

    ```bash
    package name: (my-monorepo-1)
    version: (1.0.0)
    description:
    entry point: (index.js)
    test command:
    git repository:
    keywords:
    author:
    license: (ISC)
    type: (commonjs)
    About to write to /workspaces/portfolio-nextjs-2/my-monorepo-1/package.json:

    {
        "name": "my-monorepo-1",
        "version": "1.0.0",
        "description": "",
        "main": "index.js",
        "scripts": {
            "test": "echo \"Error: no test specified\" && exit 1"
        },
        "author": "",
        "license": "ISC",
        "type": "commonjs"
    }
    ```

    自動生成された package.json にはワークスペースでは不要な項目も含まれるため、手動で削除と必要な項目を追記する。最終的に以下のようにする

    ```json
    {
      "name": "my-monorepo-1",
      "private": true,
      "workspaces": ["apps/*", "packages/*"]
    }
    ```

2.  Next.js アプリの自動生成 (apps)

    Next.js公式の CLI ツールを使って apps/web フォルダ内にアプリを自動生成する。

3.  パッケージの自動生成 (packages)

    ```bash
    npm init -w packages/logger
    ```

    実行結果

    ```bash
    package name: (logger) @my/logger
    version: (1.0.0)
    description:
    entry point: (index.js) ./src/index.ts
    test command:
    git repository:
    keywords:
    author:
    license: (ISC)
    type: (commonjs) module
    About to write to /workspaces/portfolio-nextjs-2/my-monorepo-1/package/logger/package.json:

    {
        "name": "@my/logger",
        "version": "1.0.0",
        "description": "",
        "main": "./src/index.ts",
        "devDependencies": {},
        "scripts": {
            "test": "echo \"Error: no test specified\" && exit 1"
        },
        "author": "",
        "license": "ISC",
        "type": "module"
    }
    ```

    自動生成された package.json にはパッケージでは不要な項目も含まれるため、手動で削除と必要な項目を追記する。最終的に以下のようにする。

    ```json
    {
      "name": "@my/logger",
      "version": "1.0.0",
      "private": true,
      "type": "module",
      "main": "./src/index.ts",
      "types": "./src/index.ts",
      "scripts": {},
      "devDependencies": {}
    }
    ```

4.  参照設定

    apps -> packages はソース直接参照とする。(packagesのdistは生成しない)

    各パッケージの package.json の例

    ```json
    {
        "name": "@my/error",
        "version": "1.0.0",
        ...
        "main": "./src/index.ts",
        "types": "./src/index.ts",
        "exports": {
            ".": {
                "default": "./src/index.ts",
                "types": "./src/index.ts"
            }
        },
        ...
    }
    ```

    main/types と、 exports の default/types には .ts ソースファイルを指定する。

    Next.js アプリケーションの package.json の例

    ```json
    {
        ...
        "dependencies": {
            "@my/error": "*",
            ...
        },
        ...
    }
    ```

    参照するパッケージを dependencies に記述する。

5.  ビルド設定

    各パッケージに、型チェックのスクリプトを設定する（型チェックのみとし、トランスパイルは行わない）。

    各パッケージの package.json の例

    ```json
    {
      "scripts": {
        "lint": "eslint",
        "typecheck": "tsc --noEmit" // ★これを追加
      }
    }
    ```

    Next.js アプリケーションのビルド時に参照パッケージも含めてトランスパイルする。

    Next.js アプリケーションの next.config.ts の例

    ```ts
    // next.config.ts
    import type { NextConfig } from "next";

    const nextConfig: NextConfig = {
      transpilePackages: ["@my/env", "@my/logger", "@my/client"], // ★これを追加する
    };
    export default nextConfig;
    ```

    ワークスペースのルートにビルドスクリプトを設定する

    ```json
    // package.json
    {
        ...
        "scripts": {
            "typecheck": "npm run typecheck --workspaces --if-present",
            "build:web": "npm run typecheck && npm run build --workspace=apps/web"
        },
        ...
    }
    ```
